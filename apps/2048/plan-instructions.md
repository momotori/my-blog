# Plan 서브에이전트 지침

## 목표
사용자가 요청한 "2048" 웹앱의 구현 계획을 작성한다. 이 단계에서는 **코드를 작성하지 않는다**. 오직 계획 문서만 작성한다.

## 앱 요구사항 (사용자 요청)
- 2048 게임: 방향키로 숫자 타일을 밀어서 같은 숫자끼리 합치는 퍼즐 게임
- 점수판(현재 점수, 최고 점수) 포함
- 모바일에서도 사용 가능해야 함 (터치 스와이프 지원 고려)

## 제약 조건 (CLAUDE.md 준수)
- 프레임워크, 번들러, npm 의존성 금지. 순수 HTML/CSS/JS만 사용.
- 외부 라이브러리 사용 최소화 (CDN은 허용되지만 2048 게임은 라이브러리 없이 구현 가능함).
- 모든 결과물은 `/apps/2048/` 폴더 안에 자체 완결되어야 한다. 블로그의 다른 파일(index.html, css/style.css, js/main.js, posts/ 등)은 건드리지 않는다.
- 다크 모드 대응 (블로그 전체가 다크 모드를 지원하므로, 앱도 라이트/다크 모두 보기 좋아야 한다).

## 작성할 파일
`D:/Desktop/my-blog/apps/2048/spec.md` 파일 하나만 작성한다. 다음 내용을 포함할 것:

1. **개요**: 앱이 무엇인지 한 줄 요약
2. **파일 구조**: `/apps/2048/` 안에 어떤 파일들을 만들 것인지 (예: index.html, style.css, game.js 등) 트리 형태로 제시
3. **게임 로직 설계**:
   - 4x4 보드 상태를 어떤 자료구조로 관리할지
   - 방향키(←↑→↓) 입력 처리 방식 (밀기/합치기 알고리즘 개요)
   - 새 타일 생성 규칙 (2 또는 4가 랜덤 위치에 등장)
   - 게임 오버 판정 방식
   - 승리 조건(2048 타일 등장) 처리 방식
4. **점수판 설계**: 현재 점수, 최고 점수(localStorage 저장) 표시 방법
5. **UI/스타일 계획**: 레이아웃 개요, 타일 색상 구성(숫자별 색 구분), 다크모드 대응 방법, 반응형/모바일 터치 스와이프 처리 방법
6. **블로그 통합 방법**: index.html에 카드로 추가할 때 어떤 제목/설명 문구를 쓸지 제안 (실제 index.html 수정은 이후 Embed 단계에서 진행하므로 여기서는 제안만 한다)

## 완료 조건
`spec.md` 작성을 마치면 끝. 다른 파일은 생성하지 말 것.
