## 목표
`D:/Desktop/my-blog/apps/2048/` 안에 구현된 2048 게임(`index.html`, `style.css`, `game.js`)이 `spec.md`의 계획대로 정상 동작하는지 검증한다. Build 서브에이전트가 이미 구현을 마쳤으므로, 너는 **코드를 새로 작성하지 말고 검증에 집중**한다. 단, 명백한 버그를 발견하면 최소한의 수정을 가한다.

- 블로그의 다른 파일(`index.html`(최상위), `css/style.css`, `js/main.js`, `posts/` 등)은 절대 건드리지 않는다.
- `spec.md`, `plan-instructions.md`, `build-instructions.md`는 수정하지 않는다.

## 검증 항목
1. **로컬 정적 서버로 실제 브라우저 동작 확인** (`file://`는 CORS로 막힐 수 있으므로 `python -m http.server` 등 사용):
   - 페이지가 콘솔 에러 없이 로드되는가
   - 방향키(←↑→↓)로 타일이 올바르게 밀리고 합쳐지는가 (4방향 모두)
   - 이동 후 새 타일이 정상적으로 생성되는가
   - 점수가 올바르게 갱신되고, 최고 점수가 `localStorage`에 저장/복원되는가
   - 게임 오버 판정이 정확한 시점에 발생하는가
   - 2048 타일 등장 시 승리 오버레이가 뜨고 "계속하기"/"새 게임" 버튼이 정상 동작하는가
   - "새로하기" 버튼이 보드/점수를 올바르게 초기화하는가
   - 다크모드(`localStorage.theme = "dark"` 또는 시스템 다크모드)에서 색상 대비가 충분하고 레이아웃이 깨지지 않는가
   - 모바일 뷰포트(예: 375px)에서 레이아웃이 깨지지 않고, 터치 스와이프로 조작 가능한가
2. **코드 리뷰**: `spec.md`의 설계(특히 `slideAndMergeLine` 로직, 한 턴에 이중 병합 방지, 게임오버 판정 조건)가 실제 코드에 올바르게 반영되었는지 확인. 명백한 버그(예: 특정 방향에서만 오작동, 병합 중복, 점수 계산 오류 등)가 있으면 최소한의 수정으로 고친다.
3. **프로젝트 규칙 준수 확인**: 프레임워크/번들러/npm 의존성 없음, 외부 라이브러리 미사용, `/apps/2048/` 바깥 파일 미참조.
