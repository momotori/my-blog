# 2048 게임 — 구현 계획 (spec)

## 1. 개요
방향키(또는 모바일 스와이프)로 4x4 보드의 숫자 타일을 밀어 같은 숫자끼리 합치며 2048 타일을 만드는 것을 목표로 하는 퍼즐 게임. 현재 점수와 최고 점수(localStorage 저장)를 함께 보여준다.

## 2. 파일 구조
```
apps/2048/
├── index.html      # 게임 화면 마크업 (보드, 점수판, 버튼)
├── style.css       # 레이아웃, 타일 색상, 다크모드, 반응형
├── game.js         # 게임 로직 (보드 상태, 이동/병합, 승패 판정)
└── spec.md         # 본 계획 문서
```
- 이미지/폰트 등 외부 에셋 없이 CSS로만 타일 색상을 표현한다.
- 외부 라이브러리(CDN 포함) 없이 순수 JS로 구현한다(2048 로직은 라이브러리가 필요 없을 만큼 단순함).
- `/apps/2048/` 바깥 파일(다른 앱, 블로그 본체)은 참조하지 않는다. 다크모드 등 필요한 로직은 `apps/2048/` 안에서 자체 구현하되, 블로그와 동일한 CSS 변수 이름·값 체계와 `localStorage`의 `theme` 키를 재사용해 시각적 일관성을 유지한다(같은 오리진이므로 블로그에서 설정한 테마가 자동으로 이어짐).

## 3. 게임 로직 설계

### 3.1 보드 상태 자료구조
- `board`: 4x4 2차원 배열 (`Array<Array<number>>`), 빈 칸은 `0`, 그 외는 타일 값(2, 4, 8, ...).
- 부가 상태: `score`(현재 점수), `best`(최고 점수, localStorage와 동기화), `isGameOver`(boolean), `hasWon`(boolean), `keepPlayingAfterWin`(boolean).

### 3.2 방향키 입력 처리 (밀기/합치기 알고리즘 개요)
공통 함수 `slideAndMergeLine(line)`으로 "왼쪽으로 미는" 한 줄(4칸) 처리를 담당시키고, 방향에 따라 보드를 회전/전치해서 재사용한다.

1. 방향 입력(←/↑/→/↓, 또는 스와이프) 수신.
2. 방향에 맞게 보드를 변환해 "왼쪽 이동" 문제로 통일:
   - ← : 그대로 각 행 처리
   - → : 각 행을 뒤집은 뒤 처리, 결과를 다시 뒤집어 복원
   - ↑ : 보드를 전치한 뒤 각 행을 ← 처리, 결과를 다시 전치
   - ↓ : 전치 후 각 행을 뒤집어 처리, 다시 뒤집고 전치 복원
3. 각 행에 대해: `0` 제거해 압축 → 왼쪽부터 순회하며 인접한 같은 값을 1회만 병합(한 턴에 이미 합쳐진 타일은 다시 합치지 않음, 병합 시 `gained`에 합산 값 누적) → 다시 `0`으로 채워 길이 4 맞춤.
4. 변환 전 방향으로 되돌려 `board`에 반영.
5. 실제 변화(`moved`)가 있었는지 판단 — 변화 없으면 새 타일 생성/렌더링 생략(무의미한 키 입력 무시).
6. 변화가 있으면 `score += gained 합계`, `best = max(best, score)`(localStorage 저장), 새 타일 1개 생성, 렌더링, 게임오버/승리 판정 수행.

### 3.3 새 타일 생성 규칙
- 이동 후 빈 칸(`0`) 좌표 목록에서 무작위로 하나 선택.
- 90% 확률로 `2`, 10% 확률로 `4` 배치.
- 게임 시작 시 이 과정을 2회 실행해 초기 타일 2개 배치.

### 3.4 게임 오버 판정 방식
다음 두 조건이 모두 거짓일 때 게임 오버:
1. 빈 칸(`0`)이 하나라도 있는가.
2. 빈 칸이 없다면, 인접한(상하좌우) 두 칸 중 같은 값을 가진 쌍이 있는가.
둘 다 아니면 `isGameOver = true`로 설정하고 "게임 오버" 오버레이 표시, 최고 점수 최종 저장.

### 3.5 승리 조건(2048 타일) 처리 방식
- 매 이동 후 보드에 값이 `2048` 이상인 타일이 있는지 확인.
- `hasWon`이 `false`이고 처음 발견되면 "승리" 오버레이 표시("계속하기"/"새 게임" 버튼).
- "계속하기" → `keepPlayingAfterWin = true`로 게임 계속(더 높은 타일 도전 가능), 이후 승리 오버레이 재표시 안 함.
- "새 게임" → 보드 초기화, `score = 0`, `isGameOver = false`, `hasWon = false`.

## 4. 점수판 설계
- 헤더에 `현재 점수` / `최고 점수` 두 박스로 표시.
- `score`: 메모리 변수, 매 이동마다 갱신 후 DOM 반영(새로고침 시 0부터 시작).
- `best`: 로드시 `localStorage.getItem("game2048-best")`(없으면 0)로 초기화. 매 이동 후 `score > best`면 갱신 및 즉시 저장.
- 점수 상승 시 `+n` 형태로 잠깐 떠올랐다 사라지는 애니메이션(선택적 개선 요소).
- 점수판 옆에 "새로하기" 버튼 배치.

## 5. UI/스타일 계획

### 5.1 레이아웃 개요
- 중앙 정렬 단일 컬럼, 최대 폭(약 480px) 제한.
- 상단: 타이틀(`2048`) + 점수판 + "새로하기" 버튼.
- 안내 문구: "방향키 또는 스와이프로 타일을 밀어보세요".
- 중앙: 4x4 보드(CSS Grid `repeat(4, 1fr)`, 정사각형).
- 승리/게임오버 시 보드 위에 반투명 오버레이(절대 위치) 표시.

### 5.2 타일 색상 구성 (숫자별 색 구분)
CSS 커스텀 프로퍼티/속성 선택자(`.tile[data-value="2"]` 등)로 값별 배경·글자색 매핑, 원조 2048 팔레트를 참고한 자체 배색:
- 2, 4: 연한 베이지 계열, 진한 회색 글자
- 8, 16: 주황 계열, 흰색 글자
- 32, 64: 빨강 계열, 흰색 글자
- 128~512: 노랑~금색 계열, 흰색 글자(자릿수 늘면 폰트 축소)
- 1024, 2048: 짙은 금색/강조색, 흰색 글자
- 2048 초과: 다크 강조색 계열로 통일

### 5.3 다크모드 대응 방법
- 블로그 본체와 동일한 방식(`:root[data-theme="dark"]`, `prefers-color-scheme`, `localStorage`의 `theme` 키)을 `apps/2048/` 안에 자체 구현(초기 렌더 전에 실행해 FOUC 방지).
- 블로그와 동일한 변수명(`--bg`, `--bg-secondary`, `--text`, `--text-secondary`, `--accent`, `--border`)과 색상 값을 재사용.
- 보드/빈 칸 배경은 `--bg-secondary`, 페이지 배경은 `--bg`, 텍스트는 `--text`. 타일 팔레트는 라이트/다크 배경 모두에서 대비가 충분하도록 고정 색상 사용(테마 무관).

### 5.4 반응형/모바일 터치 스와이프 처리 방법
- `viewport meta` 설정, 보드 폭은 `min(90vw, 480px)`, 타일 폰트는 `clamp()`로 반응형 처리.
- 터치 스와이프: `touchstart` 시작 좌표 기록 → `touchend`(또는 누적 `touchmove`)에서 종료 좌표 비교 → dx/dy 절대값이 큰 축으로 방향 결정. 최소 이동거리(약 20px) 미만은 무시. 보드 영역 내 스와이프 시 `touchmove`에서 `preventDefault()`로 페이지 스크롤과 충돌 방지.
- 키보드(`keydown`)와 스와이프 모두 동일한 `handleMove(direction)`으로 합류해 로직 중복 방지.

## 6. 블로그 통합 방법 (제안 — 실제 반영은 Embed 단계)
- 제목: `2048`
- 설명: `방향키나 스와이프로 타일을 밀어 숫자를 합치는 클래식 퍼즐 게임. 최고 점수를 갱신해보세요.`
- 링크: `apps/2048/index.html`
- 태그(있다면): `게임`, `퍼즐`, `JavaScript`

## 7. 구현 우선순위 (Build 단계 참고용)
1. (필수) 보드 자료구조, 이동/병합 로직, 새 타일 생성, 렌더링
2. (필수) 방향키 입력, 점수판 + localStorage 최고 점수
3. (필수) 게임 오버 / 승리 판정 및 오버레이, 새 게임 버튼
4. (필수) 다크모드 대응, 반응형 레이아웃
5. (필수) 모바일 터치 스와이프
6. (선택) 점수 증가 애니메이션, 타일 등장/병합 애니메이션, 방향 버튼 UI
